# This file is written in two passes. `env-data` records the data set below;
# `env-baseline` appends the physical-floor measurements under its own heading.
# Every number here is re-derivable from the command printed above it.

## The data set

Generated by `1brc/code/gen/cmd/measurements`, built from this repo at the commit
that added it. Unlike upstream's CreateMeasurements.java, which uses
ThreadLocalRandom and so produces a file nobody can reproduce, this generator is
seeded: rerunning the exact command below reproduces the file byte for byte, and
the sha256 is the proof.

$ cd 1brc/code/gen && go build -o /tmp/1brc-measurements ./cmd/measurements

$ /tmp/1brc-measurements -rows 10000000    -out $ASSETS/measurements-10m.txt                -seed 1
rows=10000000 stations=413 stddev=10.0 seed=1 bytes=137949720 elapsed=182ms rate=723.6 MB/s

$ /tmp/1brc-measurements -rows 100000000   -out $ASSETS/measurements-100m.txt               -seed 2
rows=100000000 stations=413 stddev=10.0 seed=2 bytes=1379567344 elapsed=1.813s rate=725.5 MB/s

$ /tmp/1brc-measurements -rows 10000000    -out $ASSETS/measurements-10k-stations-10m.txt -keyset 10k -seed 4
rows=10000000 stations=10000 stddev=7.0 seed=4 bytes=570941611 elapsed=310ms rate=1753.8 MB/s

$ /tmp/1brc-measurements -rows 1000000000  -out $ASSETS/measurements-1b.txt                 -seed 3
rows=1000000000 stations=413 stddev=10.0 seed=3 bytes=13795610267 elapsed=18.138s rate=725.4 MB/s

## Reference (expected) output

$ cd 1brc/code/gen && go build -o /tmp/1brc-reference ./cmd/reference
$ /tmp/1brc-reference -in $ASSETS/measurements-10m.txt              > 1brc/testdata/expected-10m.out
$ /tmp/1brc-reference -in $ASSETS/measurements-10k-stations-10m.txt > 1brc/testdata/expected-10k-stations-10m.out

  expected-10m.out                     10650 bytes, 413 entries, 0.79 s wall
  expected-10k-stations-10m.out       684637 bytes, 10000 entries, 0.58 s wall

These two files ARE committed (10 KB and 669 KB, well under the 5 MB limit) so the
correctness gate is self-contained and any change to the generator shows up as a
diff rather than as a silently moving target.

First 200 bytes of expected-10m.out, next to upstream's published example:

  ours:     {Abha=-24.7/18.0/54.9, Abidjan=-12.3/26.0/65.8, Abéché=-14.3/29.4/69.2, Accra=-15.0/26.4/65.9, Addis Ababa=-26.8/16.0/54.3, ...}
  upstream: {Abha=-23.0/18.0/59.2, Abidjan=-16.2/26.0/67.3, Abéché=-10.0/29.4/69.0, Accra=-10.1/26.4/66.4, Addis Ababa=-23.7/16.0/67.0, ...}   (README.md:45)

The means agree exactly (18.0, 26.0, 29.4, 26.4, 16.0) because they are the
station means from the same table and both data sets are large enough to converge
on them. The min and max differ because these are different random draws over a
different row count. This is the strongest available check that our generator
reproduces upstream's distribution, short of running upstream's Java.

## Gotcha found while verifying this data

Two of the 413 official station names contain a comma -- "Washington, D.C." and
"Flores,  Petén" (two spaces). The output format separates entries with ", ", so
the result line CANNOT be split on ", " to recover entries: "Washington, D.C."
splits into two. Byte-comparison against the reference output is the only sound
correctness check; any tool that parses the output line by splitting is wrong.

  $ grep -oE '\{"[^"]*"' 1brc/code/gen/stations.go | sed 's/{"//;s/"$//' | grep -nE '[,=]'
  124:Flores,  Petén
  396:Washington, D.C.

## Deviations from upstream's generator

1. Seeded PCG rather than ThreadLocalRandom, so the files are re-derivable.
2. Values are clamped into [-99.9, 99.9]. Upstream does not clamp; with sigma=10
   and station means in [-14.4, 30.5] the bound sits beyond 6 sigma, so the clamp
   is effectively never taken but makes conformance with README.md:422 structural
   rather than statistical. TestWriteClampsToLegalRange exercises it with an
   out-of-range station mean, since the official set can never reach it.
3. The 10k-station set is synthesised by this repo, not ported from upstream's
   CreateMeasurements3 (which slices names out of a concatenated corpus). It is a
   hash-pressure and key-count stressor, not a byte-compatible reproduction; see
   Synthetic10k in gen.go.
